Section 01Executive summary

The central question, set by the operator after reviewing v1: multi-agent systems degrade sequential tasks by 39–70 % under matched compute (Google/MIT, arXiv 2512.08296). Is that fundamental, or an artifact of bad algorithms and architecture — and what would a multi-agent design that beats single-agent look like?

The verdict

The operator's intuition is substantially vindicated, with a precise boundary. The 39–70 % figure measures the untrained-relay regime — prompt-coordinated frozen models exchanging unstructured natural-language summaries at ~4,800-token budgets. It is not a law of multi-agent systems.

What survives as genuinely fundamental is narrow and actionable: never share one context among deliberators, never hand off less than a sufficient statistic, never skip independent verification, and don't decompose short sequential tasks at all.

The degradation decomposes into four loss terms plus one offsetting term, and the 2026 record shows each loss term is either a design variable or already fixed somewhere with published numbers.

  1. The dominant term — handoff loss — is localized and trainable. An information-bottleneck result (arXiv 2607.16133) proves multi-agent and single-agent are equivalent under lossless relay: the entire gap lives in the handoff encoder. Interventions work — outcome-trained summarization cut compaction-induced error ~50 % in production (Cursor Composer); learned fold policies gained +8.8 % SWE-bench Verified at 10× smaller active context (FoldGRPO); workspace-as-state handoffs are the pattern three production teams independently converged on.
  2. Trained coordination reverses the naive deficit — including on strictly sequential tasks. Dr. MAMR flips multi-agent from below to +3.1–7.5 points above single-agent RL on competition math after fixing a provable turn-normalization bias; AT-GRPO takes sequential planning from 14–47 % to 96–99.5 %; MAKER's gated voting executed a million-step strictly sequential task at zero errors and log-linear cost.
  3. On long horizons the dichotomy dissolves. A single frontier agent retains only ~0.75–0.85 of its capability at 512K–1M tokens on retrieval-shaped work (~0.5 on structure-shaped), and every production harness compacts at 150–200K. Past that threshold the "single agent" must segment too — and the contest is decided by handoff fidelity. The console's context rotation is already a sequential multi-agent handoff; its encoder is the last 4,000 characters by recency.
  4. The honest residual. Relay-loss sensitivity grows with model capability; no trained result yet beats a matched frontier single agent on a strictly sequential benchmark; and frontier single agents are being trained up simultaneously. The race is live.

Section 03The evidence, read precisely

Token accounting decides what each study actually shows, so it is made explicit throughout.

3.1The degradation result

Google Research + DeepMind + MIT, "Towards a Science of Scaling Agent Systems" (arXiv 2512.08296). ~180–260 configurations, 5 architectures, 3 model families, standardized tools and compute.

  • Centralized coordination: +80.9 % on parallelizable tasks.
  • Every multi-agent variant degraded sequential-reasoning tasks by 39–70 % (PlanCraft).
  • Error amplification: 17.2× uncoordinated vs 4.4× centralized.
  • The paper's own rule: "switch to multi-agent only if the task decomposes and single-agent success <45 %."
Caveats that bound what the number means No SWE-bench-style coding benchmark. Headline R² is 0.513 (cross-validated 0.37–0.41). All coordination was prompt-based over frozen models — there is no trained-coordination arm. Matched budgets averaged only ~4,800 reasoning tokens per trial, so the coordination tax is proportionally enormous relative to production budgets of 50k+. No replication or author follow-up exists as of Aug 2026; the 43-paper citation wave decomposes the mechanism rather than attacking the result.

3.2The matched-budget result

Tran & Kiela (arXiv 2604.02460). Under matched reasoning-token budgets, single-agent matches or beats multi-agent on multi-hop reasoning across Qwen3, R1-Distill, and Gemini 2.5. The authors conclude that "many reported advantages of multi-agent systems are better explained by unaccounted computation and context effects." This is the cleanest statement of the null hypothesis this report must answer.

3.3The successes, with their price tags

  • Anthropic multi-agent research system: orchestrator + 3–5 parallel subagents beat single-agent Opus 4 by 90.2 % on internal research evals — a breadth-first task shape — at ~15× chat-level token cost, with token spend explaining ~80 % of performance variance. Multi-agent won partly by spending more.
  • Cognition, June 2025 → April 2026: from "Don't build multi-agents" to a measured revision — writes stay single-threaded; extra agents contribute intelligence, not actions. The robust win is a fresh-context read-only reviewer (avg 2 bugs/PR, 58 % severe), and isolation is why it works.
  • Anthropic harness-cost table: the same small app cost $9 solo vs $200 under a heavy three-agent harness. Scaffolding is a cost multiplier that must shrink as models improve.

3.4The context-management convergence

Three independent production teams abandoned in-place summarization for resets with structured handoff state: Anthropic (fresh context per feature + claude-progress.txt + machine-readable feature lists + git as memory), Amp (retired compaction for /handoff), and Factory (anchored iterative summarization, evaluated on 36,000 real session messages). OpenAI's counter-move — GPT-5.1-Codex-Max trained natively to work across context windows — confirms the same diagnosis from the training side: handoff quality is the bottleneck, so train it.

3.5The economics floor

Agent workloads run ~100:1 input:output. Cache reads cost ~0.1× base input, writes 1.25–2×; Claude Code measures 92.7 % of prompt tokens read from cache. Cache discipline is the single largest cost lever in any harness comparison — and any multi-agent design that re-establishes context per subtask pays the uncached price repeatedly.

3.6The trained-coordination record

This is the evidence both v1 and the Google study lacked. The literature that trains coordination instead of prompting it changes the picture materially.

The handoff channel is trainable

  • Cursor Composer self-summarization (shipped): the final task reward is applied to every token in the chain including mid-rollout summaries, so summaries that drop load-bearing information are downweighted by outcome. ~50 % reduction in compaction-induced error vs a highly tuned prompted baseline, at ~1,000-token summaries vs 5,000+.
  • Context-Folding / FoldGRPO: learns branch-then-fold end-to-end; +8.8 % on SWE-Bench Verified while matching ReAct with a 10× smaller active context.
  • MEM1 (ICLR 2026): RL-trained constant-size memory state — 3.5× performance at 3.7× lower memory than a 2× larger instruct model.
  • ACON: the guideline-optimization loop is gradient-free, so the optimized artifact is plain text — model-agnostic and importable by API-only harnesses today.
  • Cache-to-Cache (ICLR 2026): a learned KV-cache projection beats text communication by +3.0–5.0 % at 2× lower latency — the most direct evidence that the text handoff itself is a lossy bottleneck a learned channel can beat.

The coordination policy is trainable — and training reverses the deficit

  • Dr. MAMR — the cleanest sequential counter-example. On competition math (nothing to parallelize), the untrained multi-agent baseline underperforms single-agent GRPO, reproducing the Google pattern; trained coordination flips it to +3.1–7.5 points above. The lazy-agent failure traced to a provable turn-normalization bias — a fixable algorithm bug, not physics.
  • AT-GRPO: sequential long-horizon planning from a 14–47 % single-agent-RL baseline to 96.0–99.5 %.
  • MAPoRL (ACL 2025): co-trained models improve monotonically with collaboration turns while frozen models plateau; the skill is specifically learned collaboration and transfers across domains.
  • Kimi K2.5 Agent Swarm (production): the first shipped trained orchestrator, +17.8pp over its own single agent on wide search — and its reward penalizes decorative parallelism, so the trained orchestrator learns to stay single-threaded on sequential tasks.
The mechanism decomposition converged on the relay "When Do Multi-Agent Systems Help? An Information Bottleneck Perspective" (arXiv 2607.16133) proves MAS and single-agent are equivalent under infinite relay bandwidth — the entire degradation lives in bounded lossy relay compression, with gain = upstream-context-reduction − β·relay-loss, and β grows with model capability. "Faithful, Not Corrective" adds that strong relays are near-lossless over 6 hops (recall ≥0.973) while injected errors persist at 83–100 % through every message format — so verification, not schema, is the missing correction mechanism.

Section 04Mechanism: where the 39–70 % comes from

The degradation is not one phenomenon. It decomposes into four loss terms and one offsetting term — each with different physics, different remedies, and a different position on the fundamental/algorithmic boundary.

The four loss terms
  • L1 — Handoff information loss. Every message or reset compresses the sender's state. Implicit decisions, dead-end knowledge, and soft constraints go first — exactly what unstructured summaries drop. The console's own recorded incident: a nested identifier "lost 11 times out of 11" across message hops.
  • L2 — Error amplification. An undetected upstream error corrupts every downstream step. Uncoordinated systems amplify 17.2×; a coordinator cuts that to 4.4× by acting as an error-correcting supervisor.
  • L3 — Coordination token tax. Spawning, briefing, re-establishing context, round-trips, the coordinator re-reading reports. At matched budgets this subtracts directly from task compute — and a fresh subagent context is a cache-cold context.
  • L4 — Context fragmentation. Even with perfect messages, no participant holds the whole picture, so cross-cutting constraints are enforced by nobody. Goal drift and self-preferential bias live here.
The offsetting term
  • G1 — Context rot. The single-agent baseline is not lossless. ACON measured up to +46 % accuracy for smaller models from removing context — distraction, not just capacity. "Beyond pass@1" measured SWE-domain graceful degradation falling 0.90 → 0.44 as task duration grows, with frontier models showing meltdown rates up to 19 %.
  • G1 grows with task length. Every reset trades L1 against G1 — that trade is the entire game.

This makes the console's architecture legible: the star topology, typed mailbox and wake coalescing attack L2 and L3; ownership scopes attack L4; the durable journal makes L1 recoverable in principle; and rotation is a G1 defense whose current encoder maximizes L1.

Section 05Mathematical analysis

Assumptions are labelled [A]; measured anchors [M]. The models are deliberately simple — their job is to make the trade-offs estimable from the console's own telemetry, not to be a theory of intelligence.

5.1Handoffs as a chain of lossy channels

Let S be the task-relevant state — everything a continuation needs to finish correctly. Let X be the full interaction record that produced it, and let a handoff produce a bounded message M = f(X). Then S → X → M is a Markov chain, and the Data Processing Inequality gives:

I(S;M) ≤ I(S;X)
No post-processing of the record can add task-relevant information.

This is not merely this report's framing — it is literally the formal content of the single-agent-supremacy position. Tran & Kiela prove, for answer Y, context C, and messages M:

Pe(C) ≤ Pe(M)
Pe(X) — the smallest achievable error probability for a predictor observing only X. A predictor limited to inter-agent messages has minimum error at least that of one observing the full context.

Three qualifications determine how much that theorem actually decides:

  1. It bounds idealized observers, not architectures. Real LLMs are not Bayes-optimal on either C or M; the theorem says nothing about which system's actual predictor sits closer to its own bound.
  2. The authors themselves flag the escape (their §3.1): under degraded effective context, "once effective single-agent context utilization deteriorates sufficiently, a well-designed MAS may recover task-relevant information."
  3. The DPI is applied asymmetrically. Context degradation is tested only artificially (deletion, masking, distractors), never the organic long-context loss the same literature documents. The single agent's attention over a long C is itself a lossy channel — the inequality cuts both ways. And a message can carry results of computation; DPI bounds information, not usable computation.
The two escapes — this is where "algorithmic" enters Sufficiency. If M is a sufficient statistic for S — I(S;M) = I(S;X) — the bound costs nothing. That is achievable when state is externalized: if the workspace carries S, the message needs only a pointer and a delta. This is exactly the pattern the production convergence found.

Learned encoders. A summarizer trained so that the outcome rewards the summary is directly optimizing I(S;M) under a length budget — a learned approximation to minimal sufficiency.

And one honesty requirement: the single agent's channel is not the identity either. Carrying X forward through attention over a growing window is itself lossy — call its retention curve ρ(ℓ) at context length ℓ. The real comparison is:

I(S;M) ⏟ explicit compression vs I(S;X)·ρ(ℓ) ⏟ implicit degradation
Neither term is 1. For short tasks ρ ≈ 1 and any lossy M loses — the degradation is fundamental there. For long tasks ρ falls, and a well-engineered M can exceed what a rotted long context effectively delivers. The crossover is measurable.
Unification — the console's own architecture proves the point Rotation at 120K tokens / 30 turns is a handoff from generation n to n+1. Its encoder is recentMessages.slice(-4000) — selection by recency, the opposite of sufficiency. Single-vs-multi is not the fork in the road. Handoff fidelity is.

5.2Error propagation and the value of gates

[A] With n dependent steps at per-step error rate ε and no detection, success decays multiplicatively as (1−ε)n. Gates change that geometry — and this is now a theorem, not a heuristic. MAKER decomposes an s-step task into subtasks of m steps and runs first-to-ahead-by-k voting per step:

pstep = 1 1+ (1−pp) k pfull = (1+ (1−pp) k ) −s/m
p per-step success · k vote margin · s total steps · m steps per subtask.
With maximal decomposition (m = 1) and k growing like ln s, expected cost is Θ(p⁻¹·s·ln s) — log-linear in steps — while un-gated execution fails exponentially.

With an imperfect verifier, the production-grade version (arXiv 2607.17044) is:

p′= p(1−fb) + (1−p)cr the gate helps iff (1−p)cr > pfb
c catch rate · r fix rate · f false-alarm rate · b breakage rate.
Measured attribution: scaffolding gave +11pp, the verification loop only +1.5pp — but positionally decisive. Swapping the independent verifier for the generating model cut rescued tasks from 6 to 2: the loop's value depends on who observes.
The boundary between coordination-as-theater and coordination-that-adds Homogeneous multi-agent debate — identical inputs, shared evidence — behaves as a martingale whose expected accuracy does not improve over rounds. Agents re-reading the same context in different costumes provably gain nothing. The same work shows the loophole precisely: splitting evidence across agents monotonically decorrelates their errors (correlation 0.5 at a 50/50 split vs 1.0 under shared input). A multi-agent system earns its keep exactly when its participants observe different things — never when they share one context.

5.4The single-agent decay curve ρ(ℓ), measured

The crossover argument needs ρ to be a number, not a metaphor. Anthropic's own documentation now concedes the phenomenon by name: "as token count grows, accuracy and recall degrade, a phenomenon known as context rot."

Turn-based decay compounds the token-based curve, and is the term that matters most for the console:

  • Multi-turn accumulation itself costs ≈ 0.61× vs a fully-specified single turn (−39 % across 15 models, 200k+ simulated conversations) — and the controlled comparison isolates the cause: concatenating the same information into one turn retains 95 %, so the loss is accumulation dynamics, not capacity.
  • Realistic conversational-history retrieval is 30–60 points worse than a focused context at only ~113K tokens — the strongest measurement that an agent carrying everything is very lossy relative to a curated context.
  • Sustained vigilance over an agent transcript: needle-detection recall 99.7 % @100K → 69 % @800K.
Console anchor The rotation threshold of 120K tokens / 30 turns sits squarely inside the industry's operating band (Anthropic's server-side compaction defaults to 150K; Claude Code recommends proactive compaction at 50–60 % of window). The trigger is defensible. What the evidence indicts is the encoder — at the moment the industry says "write a structured handoff," the console writes .slice(-4000).

5.5Topology costs

Star with coordinator: O(k) messages per round; the coordinator serializes decisions (an L2 defense) but accumulates every report in its own context and adds one hop to every path. Peer-to-peer: O(k²) messages and 17.2× amplification — dominated, and the console rightly forbids it. But the console's mandatory 3-hop path means even a one-specialist sequential task pays two lossy channels where one would do.

Two 2026 measurements sharpen the coordinator's role. Orchestrators are the dominant failure source in current multi-agent systems — 67.7 % of failures vs 32.3 % for executors — and heavy-reasoning models make worse orchestrators (they over-plan the coordination itself). And self-coordination is where Princeton's 0.88× slowdown came from: pre-assigned structure, which the console's profiles, ownership scopes and enforced star already provide, is what made the 1.36× centralized speedup possible. The console's fixed topology is an asset; the missing piece is only the degenerate single-seat case.

Section 06Fundamental vs algorithmic — the answer

Multi-agent structures cannot add information, but they can add computation, error decorrelation, and independent verification. Single agents cannot lose information in principle, but they lose it in practice through context degradation no one can yet predict.

Every formal result delegates its verdict to a handful of empirical parameters — and essentially all live disagreement between the single-agent-supremacy camp and the gated-decomposition camp is disagreement about those parameters' values on real tasks, not about the math.

Fundamental — no design escapes it
  • The DPI bound. Task-relevant bits discarded by a handoff cannot be un-discarded downstream. What is escapable is discarding them in the first place — the bound is on lossy encoders, not on multi-agency.
  • The martingale bound. Participants sharing identical context provably add nothing over rounds. "More agents on the same context" is theater, permanently.
  • Coordination cost > 0. Spawn, brief, transport, re-read. Reducible several-fold; never zero.
  • The short-sequential regime. With nothing for breadth, isolation or independence to buy, multi-agent cannot win at matched budget. Kimi's trained orchestrator independently confirms it: given an outcome reward, it learns to stay single-threaded.
Algorithmic — better designs measurably don't lose it
  • Handoff insufficiency — the dominant term, and the most fixable. The IB decomposition localizes the entire gap in the relay; every intervention on it works (workspace-as-state, outcome-trained summarization, learned fold policies, and bypassing text entirely).
  • Coordination policy. Every study that reproduces the naive deficit and then trains the coordination reverses it — including on strictly sequential math and planning. The lazy-agent and consensus-collapse failures have named, fixed causes.
  • Verification structure. The gate inequality and verifier independence are design variables, not constants. Error persistence through hops means the fix is gates, not message schemas.
  • The single-agent baseline dissolves the dichotomy on long horizons. Past the rot threshold the "single agent" must segment too — facing the identical encoder-design problem.
The honest residual Three things keep this from being a full vindication of "it's just bad algorithms". (1) β grows with capability — the stronger the model, the more it loses from any lossy relay, so the algorithmic headroom shrinks as frontier long-context behavior improves. (2) No published result yet shows trained multi-agent coordination beating a matched-compute frontier single agent on a strictly sequential benchmark; the trained wins are ≤32B against same-scale baselines. (3) The frontier single agent is being trained up simultaneously. The race between trained relays and trained long context is live, and production practice currently bets on the single-writer side for sequential work.
Bottom line

The measured 39–70 % is a property of the untrained-relay regime, not a law of multi-agent systems — the mechanisms are identified, fixable, and in several cases already fixed with published numbers.

On the tasks Agentique exists for — long-horizon, partially decomposable, verification-heavy software work — a coordinated system with high-fidelity handoffs, deterministic gates, and asymmetric-observation seats has a genuine, evidence-backed path to beating any single rotting context.

Section 08Architecture directions, ranked

Each direction states its mechanism in the §4/§5 vocabulary and the telemetry that would validate it. None is an implementation commitment.

8.1Agent-authored handoffs attacks L1

Replace the 4,000-char recency slice: before rotation, and at seat close-out on long tasks, the participant writes a structured handoff — objective, decisions with reasons, hard constraints, done/remaining, failed approaches, next action, file and journal pointers — and that becomes the next generation's memory. The closing-output schema gains only taskId and status. The durable journal already guarantees nothing is lost; the handoff's job is selection, not storage.

Validation: rotation-adjacent failure and re-derivation rate; tokens spent re-reading post-rotation; task completion across rotations.

8.2Workspace as sufficient statistic attacks L1 structurally

Make externalized state the norm, not the exception: coordinators maintain a progress/decision file per session; messages carry pointers and deltas. The delegation brief already gestures at this — promote it from advice to mechanism.

Validation: message sizes, repeat-explanation tokens, L1 incident rate.

8.3Deterministic gates + one fresh-context reviewer attacks L2

Keep verification deterministic-first; the only model-based verification is a single isolated reviewer seat on risky writes — the one robust multi-agent win. Remove instructed self-verification from prompts, which current-model guidance says causes over-verification.

Validation: defects caught per reviewer token; regression rate with and without.

8.4Cache-disciplined persistent seats attacks L3

The console already resumes seats across turns — measure and protect that: stable system prompts, no mid-session model or tool changes, artifact pointers instead of re-inlined payloads. Blocked on Appendix A, since the cache split is currently invisible.

Validation: cache-read fraction per seat-turn, targeting the >90 % that Claude Code achieves.

8.5Dynamic topology: single-seat lane + star attacks L3/L1

Let main run a one-seat session reporting directly to it — no coordinator hop — and route by the §5.3 rule: single seat for sequential or short work, star for partitionable or long-horizon work, reviewer added by risk. This is the two-arm comparison that replaces v1's five-arm study.

Validation: tokens, latency and completion versus the mandatory star on comparable tasks.

8.6Model/effort tiering + escalation

Static per-profile model and effort assignment — nothing is assigned today — with one rule: failure or rotation escalates the next generation one tier. Not selected for wave 1; recorded because the telemetry makes it a one-line-per-profile experiment whenever wanted.

Section 09Recommended sequencing

  1. Telemetry first. Appendix A is complete and ready to execute. Until the cache split, model/effort identity and per-turn latency are recorded, every claim in §5 is unfalsifiable on this system.
  2. Observe real usage for the §5.3 inputs: per-task token totals by participant, rotation frequency, cache-read fractions, coordination-message share.
  3. Then the selected experiments in evidence order: agent-authored handoffs (§8.1), single-seat lane (§8.5) — each a before/after on the same telemetry.
  4. The deferred eval suite becomes worthwhile the moment any §8 change needs a controlled comparison.

Appendix ATelemetry upgrade — implementation design

Produced and validated against the codebase this session, and recorded verbatim so implementation can start without re-derivation. No code has been changed.

Verified mechanics

  • Migration machinery exists: db/client.ts runs the DDL then migrateAdditiveColumns() with pragma table_info + ALTER TABLE ADD COLUMN guards. Adding a usage_samples block there is the entire migration story.
  • The real SDK wire already carries everything needed: result messages have duration_ms, duration_api_ms, stop_reason, all four token fields, and modelUsage; the init message carries model. Effort is not echoed — record the requested effort.
  • Repo.insertUsage takes the inferred row type, so new columns compile-check every writer.
  • The fake SDK needs zero changes; all 13 existing test files pass if new fields are included only when present on the wire.
  • Known risks: runner.test.ts:36-48 asserts event order (enrich payloads, never reorder); the steer-minted follow-up turn needs its own startedAt; turns settled by the idle backstop produce no usage sample, so stamp console-measured durationMs on the settled events too; modelUsage can be multi-model per turn (persist the dominant-by-output-tokens key); web folds read payload.inputTokens as the sum.
